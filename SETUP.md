# Настройка и конфигурация

Справочник по инструментам проекта. Об архитектуре и устройстве страницы — в
[README.md](./README.md).

## Переменные окружения

Файл `.env` в корне, образец — `.env.example`.

| переменная                 | назначение                                                |
| -------------------------- | --------------------------------------------------------- |
| `NUXT_PUBLIC_SITE_URL`     | адрес сайта: карта сайта, `robots.txt`, ссылки Open Graph |
| `NUXT_PUBLIC_API_BASE_URL` | базовый адрес API, по умолчанию `/api`                    |

Обе читаются в `nuxt.config.ts` и попадают в `runtimeConfig.public`.

## Версия Node

`engines.node` требует `>=22.22.1` — это нижняя граница, её задаёт
`lint-staged`. Версия продублирована в `.nvmrc`, оттуда же её берут все задачи
CI, так что цифра живёт в одном месте:

```bash
nvm use
```

## Nuxt и Vite

`nuxt.config.ts` содержит:

- `alias` — единственный псевдоним `@` на папку `src`;
- `css` — точку входа стилей `src/app/styles/main.scss`;
- `vite.plugins` — загрузчик SVG (`vite-svg-loader`), который отдаёт иконки
  как Vue-компоненты и переводит заливки в `currentColor`;
- `vite.css.preprocessorOptions.scss.loadPaths` — благодаря этому миксины
  подключаются коротким путём `@use "shared/assets/styles/mixins" as *`;
- `app.head` — язык документа, предзагрузку шрифтов, иконку сайта и скрипт,
  который до первой отрисовки помечает документ как «JavaScript доступен»
  (нужен анимации появления, подробности в README);
- `image` — настройки модуля изображений (см. ниже);
- `typescript.strict` и `typescript.typeCheck` — типы проверяются и во время
  разработки, и при сборке.

В `tsconfig.json` продублированы псевдонимы `@`, `#app` и `#components`.
Дублирование вынужденное: корневой конфиг перекрывает карту путей из
`.nuxt/tsconfig.json` целиком, поэтому отсутствующий здесь псевдоним перестаёт
резолвиться.

## ESLint

Плоский конфиг `eslint.config.js`, набор правил:

- рекомендованные наборы Vue, `vuejs-accessibility` и TypeScript;
- Prettier как правило линтера, поэтому расхождений форматирования не бывает;
- `import/no-unresolved` с резолвером TypeScript, с исключением для импортов
  вида `*.svg?component`;
- запрет кириллицы в коде (`no-cyrillic-string`) — тексты обязаны лежать в
  словарях или моках. Отключается переменной `ESLINT_NO_CYRILLIC=0`;
- требования к компонентам: явные типы пропсов, значения по умолчанию,
  объявленные события;
- границы слоёв: `import/no-restricted-paths` описывает зоны (`shared` не видит
  ничего выше себя, `entities` не видит features и выше, и так далее), а
  `no-restricted-imports` запрещает пути вида `@/entities/*/*` — в чужой слайс
  ходят только через его `index.ts`. Зоны собираются из списка слоёв в
  `eslint.config.js`, добавлять их руками при появлении слоя не нужно.

## Stylelint

Проверяет БЭМ через `stylelint-selector-bem-pattern`. Каждый блок стилей
начинается с маркера:

```scss
<style lang="scss" scoped>
/** @define product-card */
```

Имя в маркере должно совпадать с именем блока. Файлы токенов и сброса из
проверки исключены.

## Prettier и EditorConfig

`.prettierrc.json` задаёт форматирование, `.editorconfig` — поведение
редактора. Из форматирования исключены сборки, лок-файл и сгенерированные
типы API.

## Git-хуки

Husky настраивается автоматически при `npm install`:

- **pre-commit** — `lint-staged`: ESLint и Stylelint по изменённым файлам,
  Prettier для JSON, Markdown и YAML;
- **commit-msg** — Commitlint, Conventional Commits. Разрешённые типы:
  `feat`, `fix`, `refactor`, `style`, `docs`, `test`, `chore`, `build`, `ci`,
  `perf`, `revert`.

## CI

`.github/workflows/ci.yml` запускает пять независимых задач: линтеры, проверку
типов, тесты, сборку и проверку сообщений коммитов в пул-реквестах. Версию Node
все они берут из `.nvmrc`. Переменная `HUSKY=0` отключает установку хуков в
окружении CI.

## Типы из OpenAPI

```bash
npm run generate:api                                  # из ./openapi.json
OPENAPI_SPEC_URL=https://api.example.com/openapi.json npm run generate:api
```

Результат — `src/shared/api/contracts.d.ts`. Файл сгенерированный, руками не
правится и исключён из форматирования.

## HTTP-клиент

Слой в `src/shared/api` устроен так, чтобы прикладной код не знал о транспорте:

- `client.ts` — интерфейс `ApiClient` и типы запроса и ответа;
- `adapters/axiosAdapter.ts` — единственный файл, знающий про axios;
- `index.ts` — публичный API, отдаёт готовый экземпляр как `api`.

Чтобы сменить транспорт, добавьте адаптер рядом и поменяйте одну строку в
`index.ts`. Вызовы в приложении останутся прежними.

Адаптер подгружается при первом обращении к `api`, иначе axios попадал бы в
стартовый бандл ради страницы, которая не делает ни одного запроса.

Перехватчики добавляют заголовок авторизации, показывают уведомления об
ошибках и обрабатывают ответ 401. Токен берётся не напрямую из хранилища:
`session.ts` описывает интерфейс сессии, а подставляет реализацию плагин
`plugins/session.ts`. Так транспорт из `shared` не зависит от сущности
пользователя, лежащей слоем выше.

## Изображения

Модуль `@nuxt/image` с преобразователем `ipx`. В `nuxt.config.ts` заданы две
вещи: `screens` повторяют SCSS-брейкпоинты, поэтому префикс в атрибуте `sizes`
означает в шаблоне то же, что миксин в стилях, и пресет `photo` с форматом и
качеством. Ширины мест под картинки собирает `imageSizes` из
`src/shared/config/image.ts`.

Преобразование идёт на сервере при первом запросе варианта (13–20 мс на нашей
графике) и дальше берётся из кеша.

> `ipx` тянет нативный `sharp`, и сборка кладёт в `.output` бинарники под
> текущую архитектуру. Собранную на macOS папку нельзя перенести на linux-
> сервер, собирать нужно там, где приложение будет работать.

## Сжатие ответов

`nitro.compressPublicAssets` сжимает только файлы из `public/`, отрисованная
страница уходила бы текстом. Плагин `server/plugins/compression.ts` включает
сжатие для HTML-ответов, это 199 КБ против 18 КБ на главной. За CDN или
обратным прокси это делается без нас, плагин нужен, когда приложение стоит
голым процессом.

## Уведомления

`useToast()` из `src/shared/lib` — обёртка над `vue-sonner`. Библиотека и её
стили грузятся лениво при первом уведомлении. Запрос может попросить своё
сообщение об успехе или ошибке либо промолчать:

```ts
await api.post("/subscribe", data, {
  toast: { success: t("subscribe.done") },
});
await api.get("/ping", { silent: true });
```

## Шрифты

Начертания описаны в `src/app/styles/base/_fonts.scss`, файлы `woff2` лежат в
`public/fonts/suisse-intl/`. Два основных начертания предзагружаются через
`app.head.link`.

Лицензия Swiss Typefaces требует держать файлы шрифта закрытыми от третьих
лиц, поэтому репозиторий должен оставаться приватным, а раздача шрифта
допустима только с домена проекта.

Чтобы добавить ещё одно начертание: положите `woff2` рядом, опишите
`@font-face` с нужным весом и, если оно нужно на первом экране, добавьте
предзагрузку.

## Иконки

SVG лежат в `src/shared/assets/icons/`, имя файла — это имя иконки. Заливки
заменены на `currentColor`, поэтому цвет задаётся через `color` родителя.
Чтобы добавить иконку, достаточно положить файл в папку: компонент `Icon`
находит её по имени без регистрации.

## Robots и Sitemap

Подключены модули `@nuxtjs/robots` и `@nuxtjs/sitemap`. Оба берут адрес сайта
из `NUXT_PUBLIC_SITE_URL`. Ключ `site` в `nuxt.config.ts` намеренно не
используется: при включённой проверке типов `vue-tsc` не видит его
объявления и падает.

В режиме разработки `robots` намеренно отдаёт `noindex`, в сборке —
`index, follow`.

## Тесты

`vitest.config.ts` строится через `defineVitestConfig` из `@nuxt/test-utils`,
поэтому тесты видят алиасы, автоимпорты и `#app`. Окружение — `nuxt` поверх
happy-dom. В `vitest.setup.ts` подключается экземпляр i18n для всех монтирований
и добавляются заглушки того, чего в тестовом DOM нет: наблюдатель пересечений и
методы `showModal` и `close` у элемента `dialog`.

Файлы тестов лежат рядом с кодом и попадают под линтер, включая запрет
кириллицы: там, где нужен текст интерфейса, он берётся из словаря, а не пишется
литералом.

## Зависимости и безопасность

`npm audit` показывает 13 записей, все — поддерево Nuxt (`nuxt`,
`@nuxt/nitro-server`, `@nuxt/devtools`, `vite`). Закрываются переходом на
Nuxt 4.5, который приносит мажорные Vite 8 и Vue Router 5: на них ломается
проверка типов шаблонов, поэтому обновление вынесено в отдельную задачу.

Остальное закрыто без мажоров: `axios` обновлён в пределах своего диапазона, а
уязвимые транзитивные пакеты подперты через `overrides` в `package.json`. Там
же видно, какие именно версии зафиксированы.

Имейте в виду: npm относит к прод-зависимостям почти весь сборочный
инструментарий, потому что `nuxt` и `sass` объявлены в `dependencies`. Пустого
отчёта у такого проекта не бывает.
